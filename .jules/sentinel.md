## 2026-10-31 - Prototype Pollution in vaultSet and importDocument
**Vulnerability:** A prototype pollution vulnerability exists in `vaultSet` where user input is mapped to `data[acct][field]`. Since `data` is a parsed JSON object or `{}` (both inherit from `Object.prototype`), if `acct` is `__proto__`, it accesses `Object.prototype`, and assigning to `field` pollutes all JavaScript objects globally. This gets magnified in `importDocument` which accepts user-controlled files.
**Learning:** Even internal helper methods like `vaultSet` that unpack dot-notated strings can be vulnerable if they do not validate or sanitize special object properties (`__proto__`, `constructor`, `prototype`). Furthermore, object instantiations like `const summary = {}` should be avoided for maps that might use user-controlled keys.
**Prevention:** 1. Explicitly check for and reject dangerous keys in unpack / split logic (`__proto__`, `constructor`, `prototype`). 2. Use `Object.create(null)` for mapping objects to prevent property lookups from delegating to prototypes.
